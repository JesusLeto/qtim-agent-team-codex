# qtim Doctor — самодиагностика

Read-only диагностика: ничего не чинит без подтверждения. Запускай при «что-то не работает», после обновления плагина или Codex, или при онбординге коллеги в проект с qtim-командой.

## Чеклист (прогони все пункты, собери в таблицу pass / warn / fail)

1. **Плагин.** `../../.codex-plugin/plugin.json` читается? Зафиксируй `version`. Не читается — плагин установлен нештатно: переустановка командами из `$qtim-update`.
2. **Charter и автоматически загружаемый контракт.** `.codex/team-charter.md` существует (нет -> `$qtim-setup`); первой строкой stamp `<!-- qtim-version: X.Y.Z -->` (нет -> legacy-состояние, предложи `$qtim-update`); версия stamp совпадает с версией плагина (расходится -> `$qtim-update`); track-маркеры `qtim:track:*` парные; обязательные секции на месте (roles table, model matrix, working rules, memory layout). Для stamp 2.11.0+ корневой `AGENTS.md` обязан иметь ровно одну пару `qtim:contract:start/end`; отсутствие или дубли -> warn с `$qtim-update`, но пользовательский текст вне managed region не предлагай переписывать. Для stamp 2.10.0+ model matrix проверяй только для ролей текущего charter roster: team-lead `gpt-5.6-sol` + `ultra`, присутствующие architect/reviewer Sol+xhigh, database/frontend/product Sol+high, testing Terra+medium, built-in explorer Luna+medium и ADR adversary Sol+xhigh/max; PM-only roster без reviewer/testing не является drift сам по себе. Для PM-трека проверь между маркерами оба трека (`feature-brief.md` + полный), общий checkpoint decomposition/estimate, selective consult и vertical slicing/expand-contract с DRI и contributing roles; для 2.11.0+ сводка помечена как производная self-contained, а Stage 6 пишет pointer в `memory/decisions.md` последним completion marker. Approved artifact без pointer — interrupted Stage 6, не завершённый pipeline. Для stamp 2.12.0+ PM block обязан содержать «Что запускать дальше» с recommendation/why/topology/command/alternative и запретом auto-start; managed `AGENTS.md` — explicit `$qtim-mission`, writer isolation/topological integration/final verification и запрет descendants; `memory/MEMORY.md` — on-demand `memory/missions/<slug>/`; корневой `.gitignore` — exact `.codex/qtim-runtime/`. Для stamp 2.13.0+ roles table обязан фиксировать `$qtim-minimal-diff` у присутствующих в текущем roster architect/database/frontend/reviewer с recommendation-only semantics reviewer'а, а также у однозначно распознанной qtim-generated code-writing custom role; отсутствующая стандартная роль PM-only/сокращённого roster не считается ошибкой. `memory/MEMORY.md` обязан описывать on-demand `minimal-diff:` follow-up в `retro-log.md`. Для stamp 2.14.0+ общий charter и managed `AGENTS.md` обязаны содержать exact `## Language`: `Reason internally and message peer agents in **English**` и `Keep **user-facing output in Russian**`; отсутствие -> fail с `$qtim-update`. Каждый charter 2.10.0+ обязан содержать отдельный обязательный ADR stress-test через clean-context Sol adversary и строку `adr-stress-test:` независимо от настройки code review. Если independent code review включён, charter обязан содержать всю canonical high-risk matrix: security/auth/tenant-scope visibility; money/billing/account state; documented domain invariants/public contracts; data-transform/destructive migrations; critical browser flows; high-risk performance/reliability; другое доказанно hard-to-rollback изменение, плюс обязательный read-only review при любом совпадении и явный low-risk skip.
3. **Агенты.** Для каждой роли из charter (кроме встроенных `explorer`/`worker` — им свой файл не требуется): `.codex/agents/<name>.toml` существует; TOML парсится; `name` совпадает; первой строкой `# qtim-version: ...`; нет `{{...}}` и plugin-internal путей. Для stamp 2.11.0+ присутствующий reviewer обязан иметь `sandbox_mode = "read-only"` и report section `Adversary`, а присутствующий testing — проверенную dev-команду и владение её запуском; prompt-only read-only или неизвестная команда -> fail/pending. Для stamp 2.9.0+ проверь engine markers только у присутствующих ролей: architect знает `$qtim-brainstorm`/ADR filter, database/frontend/testing — `$qtim-debug-loop`, reviewer — `skipped (low-risk diff)`. Для stamp 2.13.0+ присутствующие architect/database/frontend/reviewer должны содержать `$qtim-minimal-diff`; reviewer обязан явно различать recommendation чистой избыточности и blockers protected-zone/invariant/gate. Однозначно qtim-generated custom role без bundled template распознавай по qtim stamp + charter row + filename + совпадающему TOML `name`: если charter mission/responsibility явно code-writing, её self-contained instructions обязаны содержать `$qtim-minimal-diff`, сохранение approved scope/protected zones и одну минимальную breaking check без новой test infrastructure; отсутствие любого маркера или stamp mismatch -> fail с `$qtim-update`. Read-only/product custom role — not applicable; неоднозначная responsibility — warn/pending, не считай foreign agent qtim-owned. Для stamp 2.14.0+ `developer_instructions` каждой сопоставленной qtim role обязаны содержать полный exact `## Language` contract с English для internal/peer и Russian для user-facing output; отсутствие, partial block или конфликтующая инструкция -> fail/pending через `$qtim-update`; foreign agents не нормализуй. Model policy 2.10.0+: exact template pairs — architect/reviewer `gpt-5.6-sol`+`xhigh`, database/frontend/product `gpt-5.6-sol`+`high`, testing `gpt-5.6-terra`+`medium`; catalog-supported user override допустим; у qtim-generated custom role без template полная pair должна остаться неизменной; ровно одно поле или `model = "inherit"` -> fail.
4. **Hooks и runtime compatibility.** Отсутствие `.codex/hooks.json` — `pass`: plugin-bundled lifecycle работает без project-файла. Проверь `reference/runtime-compat.md` после Codex upgrade. `.codex/screenshots-gate.json` отсутствует -> advisory/pass; если есть, JSON обязан иметь `mode=blocking`, safe repo-relative directory без `..` и положительный freshness. Проверь matcher `qtim-testing`, один exit-2 retry и `stop_hook_active` guard; несовпавший runtime `agent_type` -> warn, не ложный pass. Project hooks проверяй по Codex nested schema; распознанные qtim-копии lifecycle -> warn как дубли; plain stdout для PostToolUse/SubagentStop -> fail. Напомни про trust review через `/hooks`; неизвестные команды не исполняй.
5. **Память и missions.** `memory/MEMORY.md` существует; файлы, на которые ссылается индекс, существуют; `memory/epic-state.md` не содержит заведомо устаревшего «в полёте» (эпик давно завершён -> warn, предложить убрать). Если есть `memory/missions/*/`, проверь наличие `mission.md`, `receipts.md`, `decisions.md`, `verification.md`; status/transition согласованы, `Done` имеет последний marker `APPROVED` и подтверждённую final evidence delivery, а `succeeded` не выдан за `validated/integrated`. State branch/worktree содержит монотонные scoped checkpoint commits только по `memory/missions/<slug>/`; partial uncommitted state блокирует resume. Writer receipt обязан иметь один scoped non-merge commit с exact per-attempt `expectedBase` parent, detached App HEAD, unchanged shared refs кроме exact coordinator-journaled state checkpoint, clean raw tree/common control и contained scopes; topological receipt integration — detached transaction-worktree cherry-pick без shared transaction ref, affected gate, exclusive promotion lock, exact-old check, `--ff-only`, final-head check и неизменный Approved HEAD при red gate. Lazy receipt перечисляет роли/responsibilities и не содержит descendants. Если есть `.codex/qtim-runtime/missions/*.json`, сначала проверь exact ignore и отсутствие tracked runtime files, затем считай ids/cursors opaque hints: JSON парсится, `schemaVersion=1`, `missionId` совпадает с portable slug, `clientThreadId` не записан как usable `threadId`, ownership содержит exact coordinator thread/host и положительную generation. Live state проверяй только через доступные `list_threads`/`read_thread`; stale/orphan/ambiguous/unavailable показывай как warn/fail, handles не угадывай. Другой live или непроверяемый coordinator блокирует takeover. Отсутствие runtime registry допустимо и означает, что resume может быть unavailable.
6. **PM-трек** (если включён в charter). Артефакты в `docs/features/*/` имеют шапку со Status; каталог использует либо `feature-brief.md`, либо полный набор, а переход трека объяснён в истории; строки-указатели в `memory/decisions.md` ведут на существующие каталоги. Продуктовая память: создана, но не вписана в read-on-start product -> warn; не создана -> info с `$qtim-product-onboard` для существующей базы.
7. **Skills.** Bundled `$qtim-debug-loop`, `$qtim-prototype`, `$qtim-brainstorm`, `$qtim-grill`, `$qtim-minimal-diff`, `$qtim-mission` должны быть доступны из установленного плагина; отсутствие -> новая задача Codex после переустановки/upgrade, а не удаление mandatory practice. Для `$qtim-mission` проверь UI policy `allow_implicit_invocation: true` вместе с fail-closed activation fixtures, App peer tools, worktree target для git writers, direct default model и Approved Sol/Ultra override только для lazy lead; отсутствие peer tools -> ожидаемый `$qtim-team-up` fallback, а не ложный pass. Отдельно проверь внешние skills из charter; недоступные -> warn и предложи убрать или установить.
8. **Roster ↔ repository responsibilities.** Возьми roster только из charter и сопоставь его с наблюдаемыми repository signals, не угадывая стек: CI/workflow/config files требуют владельца CI/operations; migration/schema directories или DB manifests — владельца data/migrations; реально существующие public UI/API/product entrypoints — владельца public/product surface; несколько независимых workspace/package roots с разными language/framework manifests — явного владельца каждого нетривиального стека. Проверяй и обратное: роль есть, а подтверждаемого слоя/обязанности в репозитории нет. Roster drift всегда `warn`, никогда `fail`, и doctor не меняет charter, agent TOML или memory. Каждая строка обязана иметь форму `repository signal -> missing/excess responsibility or role -> safe action`. Для роли, которую setup уже умеет создать, безопасное действие — отдельный повторный `$qtim-setup` с discovery, displayed plan/diff, collision handling и approval. Для responsibility без supported template напиши `responsibility gap` и верни решение decision owner: назначить существующего владельца или отдельно расширить setup. Не обещай auto-fix и не создавай роль по догадке.

## Свежесть базы знаний

Запусти только чтение: `python3 <каталог-скила>/../qtim-kb-refresh/scripts/kb_scan.py scan --base <выбранная-база>`. По умолчанию сканер берёт `origin/HEAD`. Если база недоступна или fetch не выполнялся, статус свежести — `warn/unresolved`, а не `pass`. В таблице укажи базу и sha, `delta.stale_file_count`, `delta.base_choice_required`, `validation.issues`, `overwrite.suspects` и бюджет `memory.words`. `checked` без проверяемого sha-предка базы не считай актуальным. Для дрейфа предложи ручной `$qtim-kb-refresh`; doctor не создаёт снимки, не ставит `checked` и не удаляет knowledge files. `branch_only` и расходящиеся версии требуют выбора базы владельцем.

## Вывод

Таблица: пункт · статус · что именно не так · конкретный фикс (skill, команда или правка файла).

После таблицы предложи применить **безопасные** фиксы (создание недостающего `MEMORY.md`, устаревший `epic-state.md`, распознанный qtim-дубль hooks) — по подтверждению пользователя, по одному классу за раз. Показывай diff и удаляй только qtim-owned handler, а не весь event/group с пользовательскими соседями. Миграцию версий не делай сам — отправляй в `$qtim-update`. Ничего не удаляй без подтверждения; сомнительное — только показывай.
